## Editing Legal Pages

The legal and contact routes share `src/app/components/LegalPageTemplate.tsx`. In WordPress, each route’s normal Page editor body is rendered through a `BlockArea`, so the client can compose and revise standard Gutenberg blocks without changing React code.

The text currently shown in local preview is a code fallback. It is **not automatically inserted into the WordPress Pages as saved Gutenberg blocks**. Before client handoff, transfer the approved starter text into each corresponding WordPress Page body and verify that the page uses its intended template. Saved Gutenberg content then replaces the local fallback on the frontend.

EDD system Pages use generated Hospitality templates and keep their EDD blocks in the editable WordPress Page body. In the Page editor, assign the matching template, add the corresponding EDD block, then select that Page in Downloads → Settings → General → Pages:

| EDD destination | Hospitality template | Page content |
| --- | --- | --- |
| Checkout | `CheckoutPage` | EDD Checkout block |
| Order History | `OrderHistoryPage` | EDD Order History block |
| Receipt | `ReceiptPage` | EDD Receipt block |
| Transaction Failed | `TransactionFailedPage` | EDD failure/status content provided for this destination |
| Confirmation Page | `ConfirmationPage` | EDD Confirmation block |
| Products / Shop Page | `ProductsPage` | EDD Products block |

The theme export generates templates but does not create or change WordPress Pages or EDD settings. Keep the existing EDD Page records, assign each custom template in WordPress, and map those Pages in EDD settings.
