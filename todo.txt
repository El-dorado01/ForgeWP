Local Routing (wouter or react-router-dom):
Right now, the starter only has one "page" (app/page.tsx). We could implement a lightweight router so developers can actually build multi-page prototypes (like a Dashboard) locally before exporting them to WordPress templates.

SEO & <head> Management (react-helmet-async):
Allow developers to dynamically set the <title> and <meta> tags inside React. We could then upgrade the compiler to automatically extract these tags and inject them into the WordPress functions.php or header.php.

Mock WordPress Data Hooks:
To make it a true WordPress theme builder, we need data. We could provide a dummy useWpPost() hook in src/lib/wordpress.ts. Locally, it returns fake JSON data so you can build the UI. But when compiled, the compiler transforms it into actual WordPress PHP data attributes.

A Global theme.css Token System:
Right now, Tailwind 4 handles the CSS. But we could pre-wire globals.css to read from the wp.config.ts (e.g., brand colors), so updating the config automatically themes both React and WordPress block editor styles (theme.json).
